# sbb 1.0.1, benchmark 0.9.0

Released 2026-10-27. Container image:
`ghcr.io/gorkaabad/sbb@sha256:f93c991656b7f3481dd0ab6784e0c9d3c9add7de604f6ad5315c49b6a323712d`
(`docker://` for Apptainer, see `docs/sites.md`).

Fixes from a second code review. No metric changes: the fast tests, the golden run and 12 synthetic
cells (static_patch, flashy and sneaky_dynamic against no defense, STRIP, activation clustering and
spectral signatures) give byte-identical results before and after.

- Slurm tasks with runtime apptainer bind the results directory as well as the cache.
- `sbb reproduce` takes the tolerance from the benchmark spec of the result's version.
- `sbb plan` shows the same verification status as the site, and its table and CSV share one source.
- The site's metric labels live in one place (`sbb.site.status.METRICS`).
- A frame-trigger PoisonSet holds no raw events: the DataModule triggers the cached clean frames, so
  the poisoned recordings are neither kept in memory nor encoded every epoch.
- The Game reuses the victim's clean predictions from the validity check, and an input defense
  scores the triggered batches in the same pass as the predictions, so a slow trigger runs once per
  test sample.
- `sbb zoo push` leaves out the poison_set key, which names no stored artifact.
- Still deferred, because each changes recorded numbers and needs the affected cells rerun under a
  new card version: the cached victim as the reference model of spectral signatures and activation
  clustering (the full-track networks use dropout, so skipping the reference training moves the GPU
  RNG of the retraining), and a batched dynamic trigger on the GPU.
